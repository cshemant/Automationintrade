# AIT Stock Trigger Intelligence — Dynamic Setup

## What was added

The new public page is available at:

- `/stock-triggers/`

It reads dynamic data from:

- `/market-data/stock-triggers.json`

The JSON is generated by:

- `GenerateStockTriggersJson.py`

The generator has also been connected to:

- `UpdateAllData.py`
- `.github/workflows/update-market-json.yml`

This means the trigger feed is not hard-coded in HTML. Each scheduled data run rebuilds the JSON and the browser loads the latest committed file.

## Daily update flow

1. GitHub Actions starts on its configured schedule.
2. `UpdateAllData.py --mode market` refreshes the normal market datasets.
3. `GenerateCorporateActionsJson.py` refreshes corporate actions.
4. `GenerateStockTriggersJson.py` requests recent NSE corporate announcements.
5. Announcements are classified, scored, summarised and enriched with local stock metadata.
6. Upcoming corporate actions are added as additional trigger records.
7. Recent historical triggers are retained and deduplicated.
8. `market-data/stock-triggers.json` is committed to the repository.
9. Cloudflare Pages publishes the changed JSON automatically after the Git push.

Scheduled workflow times are currently:

- Monday–Friday: 4:07 PM, 7:07 PM and 11:58 PM IST
- Saturday–Sunday: 7:07 PM IST

The generator itself can be run independently:

```bash
python GenerateStockTriggersJson.py
```

Or through the central runner:

```bash
python UpdateAllData.py --mode stock-triggers
```

## Trigger categories

The generator currently classifies:

- Order wins
- Quarterly and financial results
- Guidance and business outlook
- Capacity expansion and new facilities
- Acquisitions and partnerships
- Promoter and insider activity
- Institutional and fund activity
- Credit-rating changes
- Fund raises and dilution
- Management and auditor changes
- Regulatory and legal developments
- Corporate actions
- Other material updates

Each record contains a sentiment, impact score, concise summary, why-it-matters explanation, risk note, highlights, source link, technical-profile link and stock metadata where available.

## Source outage protection

The process does not erase the feed when NSE is temporarily unavailable.

- Recent previously generated trigger records are retained.
- Corporate-action triggers are rebuilt from local JSON.
- The output records `sourceHealthy`, `sourceMode`, `sourceError` and `sourceNote`.
- The public page visibly changes from “source healthy” to “fallback protection active”.

## Optional Gemini enrichment

AI enrichment is optional. The deterministic workflow operates without an API key.

Add the following GitHub repository secret to enable it:

- `GEMINI_API_KEY`
- `AIT_TRIGGER_AI_ENABLED` with value `true`

An optional repository variable can select the model:

- `GEMINI_MODEL`

When Gemini is unavailable or returns an error, the job continues with deterministic summaries. The AI layer is deliberately non-blocking.

## Frontend behaviour

`stock-triggers/stock-triggers.js` loads the JSON at runtime with cache-busting. It supports:

- Search by company, stock symbol or trigger text
- Category filtering
- Sentiment filtering
- Time-window filtering
- Latest, impact and alphabetical sorting
- Permanent stock timeline links such as `/stock-triggers/?symbol=RELIANCE`
- Original filing links
- Existing technical-analysis profile links
- Source freshness and fallback status

## Deployment checklist

1. Push all modified files from this package to the production repository.
2. Confirm the GitHub Actions workflow is enabled.
3. Run `Update Market JSON` manually once with mode `stock-triggers`.
4. Confirm `market-data/stock-triggers.json` is committed by the workflow.
5. Open `/stock-triggers/` and verify the generated timestamp and source status.
6. Confirm Cloudflare Pages deploys after the generated JSON commit.
7. Add the optional Gemini secrets only after the deterministic feed is stable.
8. Review NSE/exchange data usage and redistribution requirements before monetising or republishing at scale.

## Generated SEO pages

The same daily generator also rebuilds:

- `/stock-triggers/events/{event-slug}/` - source-backed event detail pages
- `/stocks/{symbol}/` - permanent company trigger hubs
- `/stock-triggers/category/{category}/` - trigger category pages
- `/stock-triggers/methodology/` - scoring, source, AI and fallback methodology
- `market-data/stock-trigger-pages-manifest.json` - generated page counts
- `market-data/stock-trigger-job-runs.json` - recent update run history and fallback status
- A managed dynamic section inside `sitemap.xml`

These pages are build-time dynamic: their facts are produced from the latest trigger JSON and regenerated by every trigger update. Obsolete generated pages are removed before each rebuild so the repository cannot accumulate stale event URLs indefinitely.

The page builder can also run independently:

```bash
python BuildStockTriggerPages.py
```

## Browser watchlist MVP

The public feed, event pages and stock hubs include a free browser-based watchlist:

- Follow or unfollow up to five stocks
- Filter the trigger feed to followed symbols
- Persist selections in the current browser through `localStorage`

This is deliberately labelled as a browser watchlist. Cross-device accounts, email delivery and paid entitlements require an authenticated backend and are not falsely represented as active.

## Public API routes

Cloudflare Pages Functions were added for:

- `GET /api/v1/triggers`
- `GET /api/v1/categories`
- `GET /api/v1/stocks/{symbol}`
- `GET /api/v1/health`

The trigger endpoint supports `category`, `sentiment`, `symbol`, `q`, `minImpact`, `limit` and cursor pagination. The APIs read the generated static assets through the Cloudflare `ASSETS` binding, so they remain aligned with the daily feed.

## D1 starter schema

`migrations/001_trigger_intelligence.sql` contains the proposed durable schema for authenticated users, watchlists, alert preferences, events, metrics, payments, entitlements, job runs and corrections.

The migration is not applied automatically. It should be deployed only when authentication, an email provider, a D1 binding and the paid entitlement workflow are ready.
